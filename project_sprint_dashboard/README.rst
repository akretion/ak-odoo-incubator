This module allows to follow what happens in a sprint, customer by
customer.

It adds a sprint dashboard based on the fortnight sprints of
``project_sprint``. For the selected customer and sprint, it shows the
tasks:

-  **Done**: tasks of the sprint in the ``Done`` state;
-  **In progress**: open tasks of the sprint with an estimate step;
-  **To start**: open tasks of the sprint without estimate step, or in
   the ``Waiting`` state;
-  **Carried over**: tasks of the sprint coming from a previous sprint.
   They are also counted in their status (done, in progress, to start).
   A task moved to a later sprint leaves the previous one.

Canceled tasks are ignored. The estimated time comes from the estimate
step of ``project_estimate_step`` (in days).

It also shows the **run** work of the sprint: tasks with a run tag of
their project (debug, urgent, out of sprint planning). For run tasks,
the time is the time spent (timesheets) when there is any, else the
estimate step. The dashboard shows how much of the sprint time was taken
by run, to see if a period was spent improving the project or fixing it.

The dashboard also shows the progress per project and the done versus
planned days of the last sprints, split between planned work and run.

To know which tasks were carried over, the module keeps the history of
the fortnight sprints of each task (``Sprint History``) and tracks the
changes of the sprint in the chatter.

Configuration
=============

-  Set a task state on every stage (``project_task_stage_state``): the
   dashboard relies on the task state, not on the stage.
-  Enable sprints on the projects and set their customer.
-  On each project using sprints, set the **Run Tags** (e.g. bug,
   urgent): tasks with one of these tags are run work.
-  Generate the sprints from the yearly sprint (Project > Configuration
   > Sprint).

Usage
=====

Go to Project > Reporting > Sprint Dashboard, or click on the
**Sprints** button of a project.

-  Select the customer and navigate between sprints with the arrows.
-  Click on an indicator, a project or a segment of a bar to open the
   corresponding tasks.
-  Click on a sprint in the history to display it.

Run tasks:

-  A run task planned in a sprint follows the normal flow.
-  A run task without sprint is put, once done, in the sprint of its
   closing date. Open run tasks without sprint are not shown.
-  The **Run** banner shows the number of run tickets, their time and
   the share of the sprint time taken by run. Click on it to open the
   run tickets.
-  A **run** badge is shown on the projects with run tickets.
-  In the last sprints, the done bar is split between planned work and
   run.

In the task list, the ``Sprint Status`` column, the **Run** / **Planned
Work** filters and the groupings are also available.
